# 微信支付接入与对公收款

> 目标：用户在小程序里付款，钱由**微信支付直接结算到公司对公账户**，平台只做下单、验签、记账，不碰资金。

## 1. 资金怎么走（先看这张图）

```
用户微信零钱/银行卡
        │  付款
        ▼
   微信支付（持牌机构）
        │  T+1 结算（扣除手续费）
        ▼
公司对公账户（商户号绑定的结算账户）
```

平台后端只做三件事：

1. **下单**：调微信支付 APIv3 生成预支付单，把参数交给小程序；
2. **验签 + 记账**：接收微信异步通知，验签、核对金额、给用户余额入账；
3. **退款**：调用微信退款接口，钱原路退回。

## 2. 为什么不能"平台先收、再转给公司"

这是最容易踩的坑，也是很多项目被叫停的原因：

- 如果用自己的收款码/个人账户/第三方聚合支付收钱，再由平台转给公司，属于**无证从事支付结算业务（俗称"二清"）**，违反《非银行支付机构监督管理条例》。
- 一旦被认定，轻则支付通道被封、资金冻结，重则行政处罚。
- 正确做法只有一个：**公司作为商户直接收单**，微信支付结算到公司对公账户。平台永远不出现"资金池"。

同理，给推荐人的佣金也不能从"平台余额"里直接转账：要么走微信"商家转账到零钱"（需单独开通权限），要么走银行代发，且都要代扣个税。

## 3. 开通前必须具备

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| 小程序主体 | 企业（个体工商户部分类目可） | 个人主体不能开通微信支付 |
| 小程序认证 | 已认证 | 未认证无法关联商户号 |
| 营业执照 | 在有效期内 | 与商户号主体一致 |
| 对公账户 | 基本户或一般户 | 结算账户必须是对公，不能是法人个人卡 |
| 小程序类目 | 教育相关，需资质 | 类目选错会被驳回，虚拟支付还受 iOS 限制 |
| 备案域名 | 已备案 + HTTPS | 回调地址必须是 https，不能带参数 |

## 4. 开通步骤（商户平台）

1. 登录 <https://pay.weixin.qq.com>，选择「接入微信支付 → 普通商户」，主体类型选**企业**。
2. 填写营业执照、法人身份证、**对公账户信息**（户名必须与营业执照一致），提交审核（通常 1–3 个工作日）。
3. 审核通过后，在「产品中心 → AppID 账号管理」关联你的小程序 AppID。
4. 在「账户中心 → API 安全」：
   - 申请 **API 证书**，下载 `apiclient_key.pem`（商户私钥）与 `apiclient_cert.pem`；
   - 记录**商户号**（mchid）与**证书序列号**（serial_no）；
   - 设置 **APIv3 密钥**（32 位，自己生成并妥善保存，丢失需重设）。
5. 在「账户中心 → API 安全 → 微信支付公钥」下载**平台公钥**（新商户）或平台证书（老商户）。本项目用平台公钥验签，更简单。
6. 配置**支付回调地址**：`https://api.你的域名.com/api/pay/notify`，退款回调：`/api/pay/refund-notify`。
7. 在「产品中心 → 开发配置」确认 JSAPI 支付已开通（小程序支付属于 JSAPI）。
8. 结算：默认 T+1 自动结算到对公账户；可在「账户中心 → 结算管理」查看。

## 5. 服务端配置

```bash
# .env
PAY_PROVIDER=wechat
WX_APPID=wx你的小程序appid
WX_SECRET=小程序secret
WXPAY_MCHID=1900000001
WXPAY_SERIAL_NO=商户证书序列号
WXPAY_PRIVATE_KEY_PATH=./certs/apiclient_key.pem
WXPAY_APIV3_KEY=32位APIv3密钥
WXPAY_PLATFORM_PUBLIC_KEY_PATH=./certs/wechatpay_public_key.pem
WXPAY_NOTIFY_URL=https://api.你的域名.com/api/pay/notify
```

**证书不要提交到 git**：`certs/` 加进 `.gitignore`，生产用密钥管理服务或服务器文件权限 600。

参数没配齐时，服务会自动退化为 `mock` 通道；而 `NODE_ENV=production` 下会**直接拒绝启动**，避免线上白送课时。

## 6. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/pay/order` | `{amountFen}` → 订单 + 拉起支付参数 |
| GET | `/api/pay/orders/:id` | 查询订单状态（前端轮询用） |
| POST | `/api/pay/notify` | 微信支付回调（验签 + 解密 + 幂等入账） |
| POST | `/api/pay/refund-notify` | 微信退款回调 |
| POST | `/api/pay/mock-pay` | **仅演示**，真实通道下返回 403 |
| POST | `/api/admin/refund` | 运营退款（需 `x-admin-secret`） |
| GET | `/api/admin/orders` | 订单列表（对账用） |
| POST | `/api/admin/close-orders` | 关闭超时未支付订单 |

小程序端：

```js
const { order, payParams } = await api.post('/api/pay/order', { amountFen: 2000 });
await new Promise((resolve, reject) => wx.requestPayment({
  timeStamp: payParams.timeStamp,
  nonceStr: payParams.nonceStr,
  package: payParams.package,
  signType: payParams.signType,
  paySign: payParams.paySign,
  success: resolve,
  fail: reject,
}));
// 然后轮询 /api/pay/orders/:id 直到 paid
```

## 7. 安全要点（代码里已经做了）

| 风险 | 处理 |
| --- | --- |
| 前端篡改金额 | 金额只由服务端从套餐生成，前端传的值只做白名单校验 |
| 伪造回调 | 必须验 `Wechatpay-Signature`（RSA-SHA256 + 平台公钥），失败直接 400 |
| 重放攻击 | 校验回调时间戳，超过 5 分钟直接拒绝 |
| 重复回调 | 订单已 paid 直接返回 SUCCESS，不重复入账（`creditTopupIn` 幂等） |
| 金额不一致 | 回调金额 ≠ 订单金额 → 订单置 `exception`，不入账，人工处理 |
| 用错商户号 | 校验回调里的 `mchid` / `appid` 与配置一致 |
| 证书泄露 | 私钥只读、600 权限、不进 git；泄露立刻在商户平台重置证书 |

## 8. 对账（每天做）

1. 商户平台「交易中心 → 账单」下载对账单，或调 `GET /v3/bill/tradebill`。
2. 与本地 `orders`（`status=paid`）+ `ledger` 三方核对：
   - 微信有、本地无 → 漏单，按 `out_trade_no` 补入账；
   - 本地有、微信无 → 虚假支付，冲正；
   - 金额不一致 → 转人工。
3. 差异超过 0.1% 要停下来查，通常是回调地址不可达或验签配置错误。

```bash
# 每天 02:00 关超时单
0 2 * * * curl -s -X POST https://api.example.com/api/admin/close-orders -H "x-admin-secret: $ADMIN_SECRET"
```

## 9. 退款规则

- 本项目只允许退**未消费的余额**（`amount <= 钱包余额`），因为课时费一旦消费就产生了模型与语音成本。
- 已消费课时要退款，需要单独的"课时退款"流程：退课时费 + 冲正佣金（`commissions.status='reversed'`），目前未实现，见《计费与佣金》第 4 节。
- 退款会原路退回，微信侧 1–3 个工作日到账。
- 退款后订单状态变为 `partial_refunded` / `refunded`，用户余额同步扣减并写 `ledger(kind=refund)`。

## 10. iOS 虚拟支付限制（必须处理）

微信小程序在 **iOS 端不允许用微信支付购买虚拟商品/服务**（课程、会员、充值都属于虚拟商品）。可选做法：

1. iOS 端隐藏充值入口，只保留免费体验与已购内容（最常见，但要注意体验一致性）；
2. 引导到 H5/公众号支付——同样违规，不要做；
3. 调整产品形态（如课程配套实物讲义），但本质仍是虚拟服务，风险不消失。

代码里可以按 `system` 判断：

```js
const sys = wx.getSystemInfoSync().platform; // ios / android
if (sys === 'ios') { /* 隐藏充值按钮 */ }
```

## 11. 税务与发票

- 收款主体是公司，按"现代服务/教育服务"确认收入并开票。
- 微信支付手续费取得增值税专用发票可抵扣（在商户平台申请）。
- 给推荐人的佣金：代扣代缴个人所得税；企业税前扣除需要合法凭证。

## 12. 上线前检查

- [ ] 商户号主体 = 小程序主体 = 对公账户户名
- [ ] 结算账户是**对公账户**，不是法人个人卡
- [ ] `PAY_PROVIDER=wechat`，`NODE_ENV=production` 能正常启动
- [ ] 回调域名 HTTPS 可达，且未被防火墙拦截
- [ ] 用 1 分钱/1 元真金白银走通一次：下单 → 支付 → 回调入账 → 账单可见
- [ ] 重复回调不会重复加钱（可让微信重试或手动重放）
- [ ] 退款走通一次，余额与订单状态正确
- [ ] 每日对账脚本跑通，差异告警
- [ ] iOS 端充值入口已隐藏或产品方案已确认
- [ ] 用户协议/退款规则/发票说明已上线

## 13. 常见错误

| 错误码 | 含义 | 处理 |
| --- | --- | --- |
| `SIGN_ERROR` | 签名错误 | 检查私钥与证书序列号是否匹配、签名串拼接是否有换行 |
| `PARAM_ERROR` | 参数错误 | 金额单位是分、`out_trade_no` 不能重复 |
| `APPID_MCHID_NOT_MATCH` | AppID 与商户号未关联 | 商户平台关联小程序 |
| `ORDERPAID` | 订单已支付 | 正常，查单而不是重新下单 |
| `NOTENOUGH` | 余额不足（退款） | 商户号余额不足，先充值 |
| `V3_NOTIFY_SIGN_FAIL` | 回调验签失败 | 平台公钥不对/未更新 |
