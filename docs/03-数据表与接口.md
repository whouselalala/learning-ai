# 数据表与接口

## 1. 表结构（12 张）

金额一律用**分（整数）**，时间一律用**毫秒时间戳（整数）**。

| 表 | 作用 | 关键字段 |
| --- | --- | --- |
| `users` | 账号与推荐关系 | `openid` 唯一、`invite_code` 唯一、`referrer_id`、`member_since`、`qualified_at`/`qualify_ordinal`（达标时刻与序号）、`summary`、`summary_upto` |
| `memories` | 长期记忆 | `UNIQUE(user_id, kind, key)`、`confidence`、`hit_count` |
| `messages` | 对话原文 | `role`、`content`、`plan_id` |
| `plans` | 学习方案 | `weeks`、`sessions_per_week`、`minutes_per_session`、`milestones_json` |
| `lessons` | 课程 | `week`、`seq`、`script`、`audio_file`、`duration_sec`、`status` |
| `wallets` | 钱包 | `cash_fen` 消费余额、`commission_fen` 可提现、`frozen_fen` 提现中、`trial_seconds_used` |
| `sessions` | 听课会话 | `started_at`、`last_beat_at`、`server_seconds`、`reported_seconds`、`billed_seconds`、`trial_seconds`、`paid_seconds`、`cost_fen`、`status` |
| `ledger` | 资金流水（只增不改） | `kind`、`balance_kind`、`amount_fen`（正入负出）、`balance_after_fen`、`ref_type/ref_id` |
| `commissions` | 佣金明细 | `earner_id`、`payer_id`、`depth`、`ordinal`（付费者是第几个直推）、`rate_bp`、`base_fen`、`amount_fen`、`status` |
| `orders` | 充值订单 | `amount_fen`、`status`、`channel`、`out_trade_no` 唯一、`prepay_id`、`transaction_id`、`paid_amount_fen`、`refunded_fen`、`expire_at` |
| `refunds` | 退款单 | `order_id`、`amount_fen`、`status`、`out_refund_no` 唯一、`refund_id` |
| `withdrawals` | 提现申请 | `amount_fen`、`status`、`channel` |

### 状态机

```
sessions.status:  active ──end()──▶ closed
                            └─余额不足─▶ insufficient
commissions.status: pending ──T+N──▶ settled
                               └─退款─▶ reversed（当前版本预留，未实现）
orders.status:      pending ──支付回调──▶ paid
withdrawals.status: pending ──运营打款──▶ paid / rejected
orders.status:      pending ──支付成功──▶ paid ──部分退款──▶ partial_refunded ──退完──▶ refunded
                        └─超时/关单─▶ closed
                        └─金额不符─▶ exception（人工处理）
refunds.status:     processing ──微信确认──▶ success / failed
```

### 为什么单独记 `ledger`

钱包余额是"结果"，流水是"证据"。任何一次余额变化都必须同时写流水，且带 `balance_after_fen`，这样对账时可以逐条校验：`上一条余额 + 本次金额 = 本次余额`。客服争议、财务对账、审计都靠它。

## 2. 接口约定

- 基址：`http://127.0.0.1:8787`
- 鉴权：`Authorization: Bearer <token>`（或 `x-token`）
- 请求/响应均为 JSON；成功 `{ ok: true, ... }`，失败 `{ ok: false, error: { code, message, ...额外字段 } }`
- 运营接口需 `x-admin-secret`

### 错误码

| HTTP | code | 含义 |
| --- | --- | --- |
| 400 | `EMPTY_TEXT` / `TEXT_TOO_LONG` / `BAD_AMOUNT` / `AMOUNT_TOO_SMALL` | 参数问题 |
| 401 | `UNAUTHORIZED` / `WX_LOGIN_FAILED` | 未登录或微信登录失败 |
| 402 | `NEED_MEMBERSHIP` | 体验额度用完且非会员 |
| 402 | `NEED_TOPUP` | 会员余额不足 |
| 403 | `FORBIDDEN` | 运营密钥错误 |
| 404 | `PLAN_NOT_FOUND` / `LESSON_NOT_FOUND` / `SESSION_NOT_FOUND` / `INVITE_CODE_NOT_FOUND` | 资源不存在 |
| 409 | `ALREADY_BOUND` | 已绑定推荐人，不可修改 |
| 400 | `SELF_REFERRAL` / `REFERRAL_CYCLE` | 推荐关系非法 |

### 开课 → 心跳 → 结算

```json
POST /api/sessions  {"lessonId": "ls_1"}
→ {"ok":true,"session":{"sessionId":"ses_1","funding":"trial","trialSecondsLeft":3600}}

POST /api/sessions/ses_1/heartbeat  {"playedSeconds": 42}
→ {"ok":true,"status":"active","serverSeconds":45,"trialSecondsLeft":3555,"estimateCostFen":0,"lowBalance":false}

POST /api/sessions/ses_1/end  {"playedSeconds": 600}
→ {"ok":true,"receipt":{
     "billableSeconds":600,"trialSeconds":600,"paidSeconds":0,"costFen":0,
     "status":"closed","funding":"trial",
     "commission":{"count":0,"totalFen":0},
     "wallet":{"cashFen":0,"trialSecondsLeft":3000}
   }}
```

超过体验后（会员、余额 20 元）：

```json
{"ok":true,"receipt":{
  "billableSeconds":600,"trialSeconds":0,"paidSeconds":600,"costFen":800,
  "status":"closed","funding":"wallet",
  "commission":{"count":1,"totalFen":160,"capped":false},
  "wallet":{"cashFen":1200,"trialSecondsLeft":0}
}}
```

`commission.count=1` 表示这笔消费只给**直接推荐人**分佣；比例取决于这个付费者是他第几个**达标**会员——第 1 个 20%（160 分）、第 2 个 50%（400 分）、第 3 个 70%（560 分），第 4 个重新回到 20%。累计消费没到 50 元时 `count=0`，佣金为 0。

## 5. 从 SQLite 迁到 PostgreSQL 的注意点

1. `TEXT PRIMARY KEY` 不用改，业务主键是字符串。
2. `INSERT ... ON CONFLICT DO UPDATE` 语法两边一致（`excluded` 同）。
3. 布尔字段现在是 0/1，PostgreSQL 建议改 `boolean`；`member_since IS NOT NULL` 的逻辑不变。
4. 并发扣余额必须改成 `UPDATE wallets SET cash_fen = cash_fen - $1 WHERE user_id = $2 AND cash_fen >= $1 RETURNING cash_fen`，用影响行数判断成功，不要"先查后改"。
5. `MAX(confidence, ?)` 在 PostgreSQL 里是同名函数，可直接用；MySQL 需 `GREATEST`。
6. SQLite 的 `PRAGMA` 相关代码删掉，连接池交给 `pg`。
