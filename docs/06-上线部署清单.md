# 上线部署清单

## 1. 服务器与进程

最低配置：2 核 4G，Node 22.5+（用到了内置 `node:sqlite`；若换 PostgreSQL 则要求不变）。

```bash
# 1) 拉代码
git clone <你的仓库> /srv/learning-ai && cd /srv/learning-ai

# 2) 配置
cp .env.example .env
# 必改：TOKEN_SECRET / ADMIN_SECRET / DEEPSEEK_API_KEY / WX_APPID / WX_SECRET

# 3) 启动（systemd）
cat > /etc/systemd/system/learning-ai.service <<'EOF'
[Unit]
Description=Learning AI
After=network.target

[Service]
Type=simple
WorkingDirectory=/srv/learning-ai
EnvironmentFile=/srv/learning-ai/.env
ExecStart=/usr/bin/node server/src/index.js
Restart=always
RestartSec=3
User=www-data

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload && systemctl enable --now learning-ai
journalctl -u learning-ai -f
```

Nginx 反代（必须 HTTPS，小程序不允许 http 与 IP）：

```nginx
server {
  listen 443 ssl http2;
  server_name api.example.com;

  ssl_certificate     /etc/letsencrypt/live/api.example.com/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/api.example.com/privkey.pem;

  client_max_body_size 2m;

  location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_read_timeout 120s;   # 生成方案/讲稿可能 30s+
  }
}
```

## 2. 环境变量核对表

| 变量 | 生产值 | 备注 |
| --- | --- | --- |
| `NODE_ENV` | `production` | 生产下没有微信配置会直接拒绝 mock 登录 |
| `TOKEN_SECRET` | 32 位以上随机串 | 泄露等于所有人可伪造登录 |
| `ADMIN_SECRET` | 强随机 | 运营接口密钥 |
| `DEEPSEEK_API_KEY` | 真实 Key | 不填会走离线规则引擎，绝不能这样上线 |
| `WX_APPID` / `WX_SECRET` | 小程序后台获取 | 用于 code2session |
| `TRIAL_SECONDS` | 3600 | 60 分钟体验 |
| `PRICE_FEN_PER_MINUTE` | 80 | 0.8 元/分钟 |
| `REFERRAL_LADDER_BP` | 建议 `[2000]` 或 `[2000,3000]` | 见合规文档 |
| `REFERRAL_CAP_TOTAL_BP` | 建议 ≤ 3000 | 单笔佣金封顶 |
| `COMMISSION_SETTLE_DAYS` | 7–30 | 越长越安全 |
| `TTS_PROVIDER` | `http` | 生产不要用 `sapi` |
| `TTS_HTTP_URL` / `TTS_HTTP_KEY` | 云 TTS 地址与密钥 | 见第 5 节 |

## 3. 微信小程序

1. 后台 → 开发管理 → 服务器域名：把 `https://api.example.com` 加进 **request 合法域名**；若音频走 CDN，再加 **downloadFile 合法域名**。
2. 类目：教育类需资质，按实际选择（在线教育/教育工具），选错类目会被驳回。
3. 隐私：填写《用户隐私保护指引》，声明收集的信息（昵称、学习情况、设备信息）；未成年人相关条款单独说明。
4. 用户协议与隐私政策：在小程序内可访问，登录页与支付页均有入口。
5. `project.config.json` 里的 `appid` 换成正式 AppID；`utils/api.js` 的 `BASE_URL` 换成 https 域名。
6. 上传前自测：体验版走一遍「登录 → 对话 → 方案 → 听课 → 充值 → 邀请」。

**iOS 虚拟支付**：小程序在 iOS 端不允许用微信支付购买课程/会员等虚拟商品。二选一：
- iOS 端只提供免费体验与已购内容，隐藏充值入口（注意体验一致性）；
- 或调整产品形态（如课程配套实物讲义），但这不改变"虚拟服务"的本质，风险仍在。

## 4. 微信支付（企业商户号 → 对公账户）

> 完整流程与安全要点见 `07-微信支付与对公收款.md`，这里只列上线动作。

1. 企业主体开通微信支付普通商户，绑定小程序 AppID，结算账户填**公司对公账户**（微信 T+1 自动结算，平台不经手资金）。
2. 下载 API 证书（`apiclient_key.pem`）、记录商户号与证书序列号，设置 APIv3 密钥（32 位），下载微信支付平台公钥。
3. `.env` 配 `PAY_PROVIDER=wechat` 及 `WXPAY_*` 六项；生产环境若仍是 mock，服务会拒绝启动。
4. 回调地址：`https://api.example.com/api/pay/notify`、`/api/pay/refund-notify`（必须 HTTPS、无参数）。
5. 用 1 元真金白银走通：下单 → 支付 → 回调入账 → 余额到账 → 退款 → 状态回滚。
6. 对账：每日拉微信账单，与 `orders` + `ledger` 三方核对，差异告警。
7. iOS 端按第 3 节处理虚拟支付限制（隐藏充值入口或调整产品形态）。

## 5. 云 TTS 接入

`server/src/lib/tts.js` 的 `synthesizeHttp` 约定：

```http
POST {TTS_HTTP_URL}
Authorization: Bearer {TTS_HTTP_KEY}
Content-Type: application/json

{ "text": "清洗后的讲稿", "voice": "zh-CN-female", "format": "wav" }
```

支持两种返回：

```json
{ "audioBase64": "..." }
{ "audioUrl": "https://cdn.example.com/xxx.mp3", "durationSec": 1180 }
```

建议：长讲稿分句合成后拼接，避免单次请求超限；音频上传对象存储，`lesson.audio_file` 存 URL（`mediaUrl()` 已兼容 http 链接）。

## 6. 数据与备份

- SQLite：`sqlite3 app.db ".backup '/backup/app-$(date +%F).db'"` 每日一次，保留 14 天；注意 WAL 模式下不要直接 `cp`。
- 上量后迁 PostgreSQL（见《数据表与接口》第 5 节），并开启 PITR。
- 音频文件：对象存储 + 生命周期规则（90 天未访问转低频/删除，课程可重新合成）。
- 备份恢复演练：每季度真跑一次恢复。

## 7. 定时任务

```cron
# 每小时结算到期的佣金（T+7）
0 * * * * curl -s -X POST https://api.example.com/api/admin/settle-commissions \
  -H "x-admin-secret: $ADMIN_SECRET" -H 'content-type: application/json' -d '{}' > /dev/null

# 每天 03:00 关闭心跳超时会话（服务内也会在开课时兜底）
0 3 * * * curl -s -X POST https://api.example.com/api/admin/close-stale-sessions \
  -H "x-admin-secret: $ADMIN_SECRET" > /dev/null

# 每日备份
30 3 * * * sqlite3 /srv/learning-ai/data/app.db ".backup '/backup/app-$(date +\%F).db'"
```

生产建议把前两个做成服务内的定时器或独立 worker，避免依赖外部 curl。

## 8. 监控与告警

必须有的四个指标：

| 指标 | 告警阈值 | 含义 |
| --- | --- | --- |
| `/api/chat` P95 耗时 | > 25s | 模型变慢或超时，用户体验崩塌 |
| LLM 失败/降级率 | > 5%（5 分钟） | Key 失效、额度用尽、网络问题 |
| TTS 失败率 | > 10% | 课程没有音频，等于核心功能缺失 |
| 佣金/充值异常 | 单笔 > 500 元、单日提现 > 2000 元 | 风控人工复核 |

日志至少包含：`traceId`、`userId`、接口、耗时、LLM 模式（deepseek/mock/fallback）、错误码。

## 9. 限流与成本控制

大模型是最贵的资源，必须先限流再谈增长：

- 按用户：`/api/chat` 每分钟 10 次，体验用户 3 次；`/api/lessons/:id/audio` 每分钟 5 次。
- 按 IP：全局 100 次/分钟。
- 会话上限：同一用户同时只允许 1 个 active 会话（当前靠"开课时关闭旧会话"兜底，建议加显式限制）。
- 缓存：同一讲稿不重复合成；方案里的 `milestones` 生成后落库，不要每次重算。

## 10. 灰度与回滚

1. 先内部 10 个账号跑 3 天，重点看：记忆是否越记越乱、方案是否可用、计费是否与手算一致。
2. 再放 100 个真实用户，观察完课率与付费转化；同时盯审核反馈。
3. 回滚方式：代码用上一个 tag；数据层不兼容的变更必须双写或可逆。
4. 计费相关改动必须有测试 + 小额灰度，**不要在大促前改钱的计算方式**。

## 11. 客服与运营 SOP

| 场景 | 处理 |
| --- | --- |
| 用户说"扣多了" | 查 `sessions` 与 `ledger`，核对 `billed_seconds` 与 `cost_fen`；误差 > 1 分立即退款 |
| 用户说"没听也扣了" | 查 `reported_seconds` 与心跳记录；超过 15 秒容差的差额退款 |
| 佣金未到账 | 确认是否满 T+7、是否已 `settled`；`pending` 状态下解释规则 |
| 提现审核 | 实名一致性、累计消费、是否自推自、是否同设备多号 |
| 内容不当 | 下线该课、清缓存、回滚提示词、记录样本进评测集 |
