# 瓦兰卡AI伴学 · 接 DeepSeek 的个性化学习小程序

用对话摸清学生情况 → 生成可执行的周计划 → 把每周的课变成**音频课** → 按收听时长计费 → 推荐分佣（每 3 个一轮循环）。

代码可直接运行：后端零依赖（Node 24 内置 `node:sqlite` + `fetch`），没配 DeepSeek Key 时自动进入离线规则引擎，全链路照样能跑通。附带一个浏览器演示台和一套微信小程序源码。

```
┌─────────────┐   对话/画像   ┌──────────────┐   方案/讲稿   ┌──────────┐
│ 小程序/网页  │ ───────────▶ │  Node 后端    │ ───────────▶ │ DeepSeek │
│  音频播放    │ ◀─────────── │ SQLite + 计费 │ ◀─────────── │   API    │
└─────────────┘   账单/佣金   └──────┬───────┘   音频文件    └──────────┘
                                     │
                              语音合成 TTS（可插拔）
```

## 1. 已经做出来的东西

| 你的需求 | 落地情况 |
| --- | --- |
| 接入 DeepSeek 大模型 | `server/src/lib/llm.js`，走 OpenAI 兼容协议；对话、画像抽取、方案、讲稿、摘要五类任务各有提示词 |
| 为学生提供个性化学习方案 | 对话中抽取年级/科目/薄弱点/时间，生成 N 周方案（里程碑 + 每周交付物 + 专题） |
| 长期记忆 | `memories` 表按 `kind+key` 覆盖更新，置信度加权注入提示词；长对话自动滚动摘要；用户可逐条查看与删除 |
| 只提供音频课程 | 每节课先生成纯口语讲稿（无 Markdown、公式读法化），再合成音频；本机 TTS 不可用时降级为文本 + 计时 |
| 课程按客户要求设定 | 方案参数（周数、每周节数、单节时长）由对话或接口传入，课程内容按记忆里的薄弱点生成 |
| 60 分钟免费体验 | 按秒累计，不按次重置；体验期内不扣费、不产生佣金 |
| 60 分钟后需注册会员 | 体验耗尽且非会员时，开课接口返回 `402 NEED_MEMBERSHIP` |
| 会员 0.8 元/分钟 | 按秒精算到分（`round(秒 × 80 / 60)`），余额不足只扣得起的部分并标记 `insufficient` |
| 推荐分佣 20%/50%/70% 循环 | 会员累计消费满 50 元才计入序号；每 3 个达标会员一轮：第 1 个 20%、第 2 个 50%、第 3 个 70%、第 4 个回到 20%…只算直推，单笔封顶 100% |
| 提现 | 佣金 T+7 结算转入可提现余额，提现申请进入冻结，运营侧打款 |

## 2. 三分钟跑起来

```bash
cd learning-ai
node -v            # 需要 >= 22.5（用到内置 node:sqlite）
npm start          # 或 node server/src/index.js
```

打开 <http://127.0.0.1:8787/> 就是浏览器演示台：填个称呼 → 聊两句 → 生成方案 → 生成本周音频课 → 开始听课 → 账单里能看到体验额度与扣费 → 「推荐有礼」页看团队与佣金。

想接真实模型，把 `.env.example` 复制成 `.env` 并填 `DEEPSEEK_API_KEY`，重启即可（其余不用改）。

支付配好后先跑自检：`node server/scripts/pay-check.js --live`，返回 `ORDER_NOT_EXIST` 说明商户号、证书序列号、私钥三者匹配。

小程序：用微信开发者工具导入 `miniprogram/` 目录，`appid` 用测试号；开发阶段在「详情 → 本地设置」勾选**不校验合法域名**。上线前记得把 `utils/api.js` 里的 `BASE_URL` 换成已备案的 https 域名。

## 4. 关键参数都在 `config.js`，改环境变量即可

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `TRIAL_SECONDS` | 3600 | 免费体验总秒数（累计） |
| `PRICE_FEN_PER_MINUTE` | 80 | 会员单价（分/分钟），80 = 0.8 元 |
| `REFERRAL_MODE` | cycle | `cycle`：每 3 个达标会员一轮循环；`depth`：按推荐层级；`sequence`：递增到 70% 不回落 |
| `REFERRAL_LADDER_BP` | [2000,5000,7000] | 每轮内第 1/2/3 个的比例（万分比） |
| `REFERRAL_QUALIFY_FEN` | 5000 | 累计消费满 50 元才计入序号；设 0 表示首单即计入 |
| `REFERRAL_CAP_TOTAL_BP` | 10000 | 单笔消费佣金总额上限，防止平台倒贴 |
| `COMMISSION_SETTLE_DAYS` | 7 | 佣金结算等待天数 |
| `TTS_PROVIDER` | sapi | `sapi` / `http` / `mock` |
| `PAY_PROVIDER` | 自动 | `wechat`：微信支付 APIv3；`mock`：仅演示（生产会拒绝启动） |
| `WXPAY_MCHID` / `WXPAY_SERIAL_NO` | — | 企业商户号与 API 证书序列号 |
| `WXPAY_APIV3_KEY` | — | 32 位 APIv3 密钥，回调解密用 |
| `WXPAY_PRIVATE_KEY_PATH` / `WXPAY_PLATFORM_PUBLIC_KEY_PATH` | — | 商户私钥、微信支付平台公钥 |
| `WXPAY_NOTIFY_URL` | — | 支付回调地址，必须 HTTPS |

## 6. 上线前请务必先读

`docs/05-合规风险与整改建议.md`。两件事必须提前决策，否则代码写得再对也上不了线：

1. **按"第几个达标会员"递增比例 + 最高 70% 计提**，本质仍与"发展人员数量"挂钩，有被认定为传销式计酬的风险，微信审核对多级/团队计酬也一直收紧。代码已做成可配置（默认每 3 个一轮、单笔封顶 100%），但商业模型建议再压到固定 20% 或改为非现金激励。
2. **面向中小学生的学科类课程**属于"双减"监管范围，微信"教育"类目审核极严，iOS 端还有虚拟支付限制。
3. **收款不能"平台代收再转给公司"**，这属于无证支付结算（二清）。必须用企业商户号直连，钱由微信支付结算到对公账户，详见 `docs/07-微信支付与对公收款.md`。

文档里给了替代方案和逐条整改清单。

## 7. 已知限制（演示版）

- 微信支付已按 APIv3 实现（下单 / 回调验签 / 幂等入账 / 退款 / 关单），但**没有真实商户号就跑不通真金白银**；未配置时自动走 `mock` 通道，生产环境会拒绝启动。
- 已消费课时的退款与佣金冲正未实现（目前只退未消费余额）。
- 未接真实微信登录：无 `WX_APPID` 时用 `mock_` 前缀的 openid；生产必须配 `WX_APPID/SECRET`。
- 本机语音合成在部分受限环境会失败（返回 `0x80045040`），此时课程降级为文本 + 计时；生产请接云 TTS。
- 计费依据「服务端会话时长」与「客户端上报播放时长」取小，并对单次会话设 4 小时上限；更强的防作弊需要音频分片鉴权（见架构文档）。

## 虚拟支付部署

瓦兰卡AI伴学使用微信小程序道具直购。微信后台发布固定面额的听课额度商品，
在服务器 `.env` 中设置 `PAY_PROVIDER=virtual`，并填写 `WX_APPID`、`WX_SECRET`、
`VIRTUAL_PAY_OFFER_ID` 和对应环境的 AppKey。
`VIRTUAL_PAY_PRODUCTS_JSON` 的键为商品价格（分），值为微信后台的商品 ID，例如
`{"1000":"learning_credit_10"}`。用户买的是用于站内按分钟扣减的学习额度。
请在虚拟支付后台确认该商品类型和商品描述适用于本业务。

沙箱用 `VIRTUAL_PAY_ENV=1` 和 `VIRTUAL_PAY_APP_KEY_SANDBOX`，在独立环境联调。
现网用 `NODE_ENV=production`、`VIRTUAL_PAY_ENV=0` 和 `VIRTUAL_PAY_APP_KEY_PROD`。
分开保存沙箱和现网数据库。生产需配置两个独立的 32 字符以上服务密钥。
微信开发者工具导入 `miniprogram/` 时选择自己的正式 AppID；小程序后台将
`https://learning-api.walankaai.com` 加入 request 合法域名。Ubuntu 上通过
`TTS_PROVIDER=http` 和兼容的 `TTS_HTTP_URL` 提供真实音频。

支付后由服务器查询微信订单，核对订单号及实付金额，再事务性入账。定时任务
继续检查未结订单，覆盖用户支付后退出的情况。现网启用前用体验版验证支付、
退出后到账、重复确认、音频播放及扣费。虚拟支付退款及相应权益冲正需另接，
现有普通微信支付退款接口不会处理虚拟订单。先明确退款与权益冲正流程，再开放真实收费。
